Forecast-Informed Drone Heading Prototype

Explore how a next-hour wind forecast can be used to rank demonstration travel headings for a future water-quality drone.

This is an unfinished research prototype. The data and forecast results are still being checked. It does not show battery savings.

How to use this demonstration

  1. Select a historical target hour and load the example.
  2. Compare the forecast wind with the observed wind.
  3. Review the headings ranked using the forecast.
  4. Compare the selected heading with a persistence-based choice using the wind actually observed.

1. Forecast the wind

The forecasting pipeline uses the previous 24 hourly weather observations to predict the following hour's eastward and northward wind components (u and v for weather nerds). The table displays those components as wind speed and direction.

This replay uses Ridge regression (similar to a linear refression). Naive Persistence (using the last value as the next) and an LSTM (Long-Short-Term-Memory Model) are also included in the forecasting experiments. Their inclusion does not establish that any model is better until the data is validated.

2. Rank demonstration travel headings

The decision layer uses the forecast wind to calculate the opposing-wind component for each candidate heading. Lower scores mean < predicted wind directly opposing travel under this simplified calculation.

Wind direction describes where the wind comes from. Travel heading describes where the drone would move. Bearings are clockwise from north.

3. Evaluate the selected headings

Two policies choose from the same candidate headings. The Ridge-based policy uses the model forecast. The persistence-based policy assumes the next hour's wind components will match the latest input hour.

Each policy's selected heading is then scored using the wind actually observed during the target hour, rather than the forecast that selected it.

How this connects to the research

My previous project focused on local wind prediction. This year's project investigates whether those predictions can inform operating decisions for an autonomous water-quality drone in Barnegat Bay.

This replay demonstrates the connection between a forecast and a decision. Testing the battery-efficiency hypothesis will require measured energy consumption during comparable sampling missions.

This score is not a battery-consumption model or a navigation instruction. It excludes currents, waves, obstacles, sampling constraints, return travel, and propulsion characteristics. Do not use this demonstration to operate a real vehicle.
